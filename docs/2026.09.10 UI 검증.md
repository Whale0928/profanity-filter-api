# 개발자 포털 UI 검증

2026.09.10 기준 로컬 http://127.0.0.1:5173/ 화면을 Orca CLI로 확인하고 수정했다. 기존 색상, 서체, 아이콘과 라우팅 구조를 유지했다. UI 수정과 정책 초안 작성은 Orca orchestration으로 분담했으며, 정책은 Opus, 인증·문서 수정은 Sonnet이 담당했다.

## 시각 비교

비교 기준은 소개 화면의 같은 CSS viewport 1469 × 812이다. 수정 전 이미지는 2배 밀도의 원본을 1469 × 812로 정규화했으며 수정 후 이미지는 1배 밀도다. 두 이미지를 나란히 열어 확인했다.

## 동작 확인

- 소개, API 문서, 로그인, 개인정보 처리방침, 이용약관을 실제 브라우저에서 확인했다.
- QUICK, NORMAL, FILTER 버튼을 눌러 선택 상태와 결과 문구가 바뀌는지 확인했다. 예시는 실제 API를 호출하지 않는 고정 시연이며 화면에도 표시했다.
- 요청 예시 복사 성공 안내를 확인했다. 요청에는 HTTPS 주소, 인증 헤더, Content-Type과 JSON 본문이 포함된다.
- 소개 화면 너비 320, 390, 764, 1024, 1280에서 가로 넘침이 0이었다.
- 모바일 API 문서 목차 열기·닫기, 항목 선택 후 닫힘과 앵커 이동을 확인했다.
- 개인정보 처리방침 목차 이동과 각 정책 페이지 제목, 390 × 844 화면에서 가로 넘침이 없음을 확인했다.
- 테마 전환 후 문서 본문과 Scalar 화면이 함께 변경되는지 확인했다.
- 익명 상태에서 /app/keys에 접근하면 /login으로 이동했다.
- 최종 새 브라우저 탭에서 소개·로그인·개인정보 처리방침·문서를 열었으며 콘솔 오류와 경고는 없었다. 중간 개발 단계의 HMR 오류가 남은 이전 탭 로그와 구분했다.

시각 검증 최종 결과: passed. 점검한 화면에서 추가로 수정할 시각적 결함은 발견하지 못했다.

## 빌드와 회귀 검증

실행 명령:

```sh
cd ui/app
npm run build
npm run verify:discovery
```

TypeScript와 Vite 빌드가 통과했고 공개 탐색 산출물 5개 검증도 통과했다. Scalar 번들의 500 kB 초과 경고는 남아 있다.

저장소 루트에서 실행한 명령:

```sh
./gradlew --no-daemon :profanity-api:spotlessApply staticCheck :profanity-api:unitTest :profanity-api:e2eTest :profanity-domain:test
```

종료 상태 0과 BUILD SUCCESSFUL을 확인했다. 최종 XML 결과는 API 단위 테스트 115개, API E2E 60개, 도메인 테스트 61개이며 총 236개 모두 통과했다. 실패·오류·건너뜀은 각각 0개다. 로그아웃 시 refresh 세션 폐기와 쿠키 만료, CSRF 차단, 쿠키 없는 요청의 멱등성, 공개 OpenAPI의 HTTPS 서버와 인증 입력 중복 제거를 포함한다.

## 적용 범위와 남은 사항

로그아웃은 서버가 성공을 확인한 뒤 UI 인증 상태를 지운다. 실패하면 재시도 안내를 표시한다. 이미 발급된 access JWT의 유효기간 정책은 변경하지 않았다. 실제 소셜 로그인, 개인 계정의 키 발급·재발급·만료는 실행하지 않았다.

문서 화면은 운영 서버의 OpenAPI를 읽는다. HTTPS 서버 URL과 중복 헤더 수정은 로컬 백엔드 코드와 E2E로 검증했으며, 운영 문서에 반영하려면 백엔드 배포가 필요하다. 새로운 로그아웃 API 역시 백엔드 배포 전 운영 연동은 미검증이다. 배포와 Git 쓰기 작업은 수행하지 않았다.

정책은 검토 초안이다. 공개 문의 이메일과 코드에서 확인되는 처리 항목은 반영했으며, 운영 주체·보관 기간·외부 AI 제공·위탁 및 국외 이전의 미확정 사항은 추정하지 않았다. 자세한 근거는 [정책 확인 사항](<2026.09.10 정책 확인 사항.md>)에 기록했다. 실제 운영 데이터와 시크릿은 열람하지 않았다.
