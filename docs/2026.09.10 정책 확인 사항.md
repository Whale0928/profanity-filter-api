# 2026.09.10 정책 확인 사항

개인정보 처리방침과 이용약관 초안을 작성하면서 확인한 근거와, 운영자가 결정해야 확정할 수 있는 항목을 정리한 내부 문서다.
대외 초안은 `ui/app/src/legalContent.ts`에 데이터로만 작성했고, 방침과 약관 모두 9개 절로 구성했다.

이 문서는 내부 확인용이다. 구현 세부와 미비점은 여기에 남기고 대외 문서에는 옮기지 않는다.

## 1. 코드에서 확인한 처리 현황

아래 내용은 저장소의 코드를 직접 읽어 확인한 사실이다. 운영 데이터베이스의 실제 상태는 확인하지 않았다.

### 필터링 요청 기록

`records` 테이블의 저장 항목은 `profanity-domain/src/main/java/app/domain/record/Records.java:34-61`에 정의되어 있다.
요청 추적 식별자, 처리 모드, API Key의 SHA-256 해시, 요청 텍스트 원문, 검출 단어, referrer, 요청 IP, 요청 시각이다.
요청 텍스트는 `requestText` 컬럼에 가공이나 암호화 없이 평문으로 저장된다.

저장 지점은 `profanity-domain/src/main/java/app/application/event/TrackingRecorder.java:36`의 `recordTracking`이며, 동기와 비동기 필터링 모두 `DefaultProfanityHandler.requestFacadeFilter`를 거치므로 이 경로를 탄다.
`POST /api/v1/filter/advanced`는 `FilterEvent`를 발행하지 않아 `records`에 남지 않지만, `profanity-api/src/main/java/app/presentation/ProfanityController.java:113`에서 요청 단어가 서버 로그에 그대로 출력된다.

요청 IP는 `profanity-api/src/main/java/app/application/HttpClient.java:24`의 `getClientIP`가 추출하며 `CF-Connecting-IP`를 우선 사용한다.

### 삭제와 보관

`RecordRepository`에 `delete`가 선언되어 있으나(`profanity-domain/src/main/java/app/domain/record/RecordRepository.java:14`) 운영 코드에서 호출하는 지점을 찾지 못했고, 보관 기간이 지난 기록을 정리하는 스케줄러도 없다.
다만 이것은 코드에 자동 파기 경로가 없다는 사실일 뿐이며, 운영 중 수동 정리가 있었는지는 확인하지 않았다. 그러므로 "모든 기록이 계속 남아 있다"고 단정하지 않는다.
대외 문서에는 보관 기간을 확정 전으로 표시했다.

요청 텍스트의 자동 비식별 처리, 학습 활용 거부 설정, 이용자가 직접 실행하는 삭제 기능, 계정 삭제 기능은 구현되어 있지 않다.
`UserAccount.disable`은 정의만 있고 운영 코드에서 호출하지 않는다.
대외 문서에서 이 기능들을 제공한다고 적지 않았고, 미구현 목록을 나열하지도 않았다.

### 계정과 인증

계정 정보는 `UserAccount.java:38-52`, 소셜 연결 정보는 `OAuthAccount.java:43-61`에 정의되어 있다. 지원 제공자는 `OAuthProvider`가 정의한 Google과 GitHub다.
API Key 정보는 `ApiKey.java:44-78`에 있으며 원문 대신 `keyHash`와 `keyHint`만 저장한다. 만료시켜도 행은 남고 `expiredAt`만 채워진다.

세션 유효 기간은 `profanity-api/src/main/resources/application-sso.yaml:44-60`에서 확인했다.

| 항목 | 기본값 |
| --- | --- |
| 로그인 교환 코드 | 60초 |
| 갱신 토큰 | 14일 |
| 절대 세션 | 30일 |
| 접속 토큰 | 15분 |

대외 문서에는 이 가운데 이용자가 체감하는 14일과 30일만 적었다.

### 캐시와 외부 연동

필터 응답 캐시는 Caffeine 기반 로컬 캐시로 만료 24시간, 최대 1,000건이다(`profanity-api/src/main/java/app/config/LocalCacheType.java:9`). 캐시 키가 요청 텍스트를 포함한다.
메일 발송 설정(`MailConfig.java`)과 Redis 설정은 존재하지만 이를 사용하는 운영 코드를 찾지 못해 대외 문서의 처리 항목에 넣지 않았다.
프런트엔드 소스와 `ui/app/index.html`에서 분석·광고 추적 스크립트를 찾지 못했으나, 배포 환경까지 확인한 것은 아니므로 "추적하지 않는다"는 단정은 대외 문서에서 뺐다.

## 2. 사실관계의 확실성 구분

- 확인된 사실: 요청 텍스트와 처리 결과가 저장되고, 이를 오류 분석과 사전 정비, 필터 연구 및 학습에 활용한다는 점은 운영자가 확인해 준 사실이다. 대외 문서에 목적으로 명시했다.
- 확인 불가: 요청 텍스트를 외부 사업자의 인공지능 서비스에 제공하는지는 코드로 확인할 수 없었다. 대외 문서에는 확인 중이며 확정되면 적겠다고 표기했다.
- 검증 실패로 삭제한 표현: 개인정보를 판매하지 않는다는 단정, 광고 추적을 하지 않는다는 단정, 단어 사전 전체의 소유권이 운영자에게 있다는 단정은 근거를 확인하지 못해 제거했다.
  제3자 제공은 "법령에 근거가 있거나 이용자가 동의한 경우가 아니면 제공하지 않는다"는 약속 형태로 바꾸었고, 사전 권리는 오픈소스 라이선스와 제3자 권리를 존중한다는 문장으로 바꾸었다.

## 5. 운영자가 결정해야 할 항목

1. 운영 주체의 상호와 대표자, 사업자 형태. 보호책임자 표기 방식이 여기에 달려 있다.
2. 요청 텍스트와 처리 결과, 접속 기록의 보관 기간과 파기 방법.
3. 계정 정보와 API Key 발급 이력의 보관 기간, 이용 종료 후 처리 방식.
4. 요청 텍스트를 외부 인공지능 서비스에 제공하는지 여부와, 제공한다면 사업자명·국가·목적·보유 기간.
5. 수탁자 목록과 위탁 업무 범위, 각 사업자의 데이터 처리 국가. 국외 이전 항목은 이것이 정해져야 채울 수 있다.
6. 열람과 삭제 요구를 접수했을 때의 처리 절차. 현재는 화면 기능이 없으므로 수동 절차를 정해야 한다.
7. 요금 부과 여부와 요청 한도.
8. 서비스 종료나 비호환 변경의 공지 기간 기준.
9. 개인정보 처리의 법적 근거를 계약 이행으로 볼지 정당한 이익으로 볼지에 대한 판단. 요청 텍스트를 필터 개선에 활용하는 부분은 특히 근거를 명확히 정해야 한다.
10. 시행일자와 이전 버전 보관 방식.

## 6. 최종본에 반영한 편집 방침

- 초안 안내 문구는 한 문장으로 줄였다.
- 개인정보 항목을 계정 정보, 요청 텍스트와 처리 결과, 접속 기록, 인증 정보 네 묶음으로 정리해 중복을 없앴다.
- 요청 텍스트의 수집·보관과 필터 연구·학습 목적은 흐리지 않고 그대로 유지했다. 이용 목적 절 첫 문장에 명시했다.
- 평문 저장, SHA-256, 미구현 기능 목록, 서버 로그 출력 내용, 캐시 구현 방식처럼 내부 구현과 약점을 드러내는 서술은 대외 문서에서 빼고 이 문서로 옮겼다.
- "감추지 않고 밝힙니다" 같은 자기 언급 문장을 지우고 담백한 서술로 바꾸었다.
- 권리 행사 안내에서 API Key 원문을 보내도록 요구하지 않도록 고쳤고, 보내지 말라는 문장을 넣었다.
- 약관의 책임 조항을 이용자 책임만 나열하지 않고 운영자가 관계 법령에 따른 책임을 진다는 문장으로 시작하도록 고쳤다.
- 권리 귀속 조항에 오픈소스 라이선스 준수와 제3자 권리 존중을 넣었다.

## 7. 후속 작업

- 운영자 답변을 받아 5항의 항목을 채우고 대외 문서에 반영한다.
- 보관 기간이 정해지면 파기 절차를 구현하고 방침의 보관 기간 절을 갱신한다.
- 최종본 확정 전에 국가법령정보센터에서 법 제30조, 제28조의8, 시행령 제31조와 제32조의 조문 전문을 사람이 직접 대조한다.
- 방침과 약관을 공개 경로에 연결하고 시행일자를 표기한다.

## 최종 통합 검토

대외 초안은 요청 텍스트의 수집·보관과 연구·학습 목적을 명시하되 저장 형식, 해시 알고리즘, 미구현 기능 목록을 본문에서 제외했다. 단어 등록·변경 요청 및 API Key 발급자 정보와 메모를 수집 항목에 보완했다. 인증 유효기간을 기록 보관 기간과 구분하고, 검증하지 않은 모든 통신 구간의 암호화는 단정하지 않았다. 쿠키 차단 방법, 권한 없는 콜백 요청의 금지, 이용 중단 방법 및 각 당사자의 귀책사유에 따른 책임을 보완했다.

이 초안의 작성 및 포털 노출만으로 요청 원문의 학습 활용에 필요한 법적 근거가 갖춰지지는 않는다. 처리 목적별 근거, 필요한 동의 또는 계약, 제3자 텍스트에 대한 권리 관계를 확정해야 한다. 운영 데이터 조회와 변경, 보관 기간 설정, 삭제 작업은 수행하지 않았다.
